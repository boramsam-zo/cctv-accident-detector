# FE — Streamlit 검토 화면

기준: [PRD](../../PROJECT_BRIEF.md) · [공통 계약](../contracts/service_contract.md). 이 문서는 화면 개발 명세다. 기존 로컬 읽기 전용 화면은 참고 구현이며 새 서비스 연결 완료로 표시하지 않는다.

## 책임과 흐름

사용자가 영상 접수→분석 요청→후보 근거 확인→설명/문서/보고 검토→판단 저장을 수행하게 한다. API 응답을 표시하고 입력을 검증해 전송한다. GPU 호출·DB 수정·문서 검색은 BE 연결점을 사용한다.

| 영역 | 사용자 행동 | 필요한 응답 |
|---|---|---|
| 접수 | 파일 업로드 또는 등록 영상 선택 | video ID, 접수 오류, 지원 범위 |
| 작업 목록 | 분석 요청, 기존 작업 다시 열기 | job/run ID, 상태, 생성시각, 후보 수 |
| 후보 상세 | 원본·클립 재생, 프레임·원본 시각 비교 | Event, Asset URL, coverage |
| 보고 영역 | 설명·출처·미확인 내용 열람 | 단계 상태, VLM/RAG/report |
| 검토 | 3가지 판단 중 선택, 메모 저장 | 검토 ID·revision·저장시각·충돌 오류 |

## Streamlit 구현 기준

- 업로드와 분석 제출을 분리한다. 명시적인 form 제출로 POST를 한 번 보내고 재전송은 같은 Idempotency-Key를 사용한다.
- `st.session_state`에는 선택한 job/run과 UI 상태를 둔다. 영구 결과는 API에서 재조회한다. 작업 목록을 통해 브라우저 재접속 후에도 열 수 있어야 한다.
- 상태 영역은 `st.fragment(run_every=...)`로 짧게 갱신하는 방식을 제안한다. terminal 상태에서는 자동 조회를 멈춘다. fragment는 활성 세션 동안만 갱신되므로 BE 작업 실행을 이 기능에 맡기지 않는다. [Streamlit 공식 fragment 문서](https://docs.streamlit.io/develop/api-reference/execution-flow/st.fragment).
- 변경 요청 POST를 캐시하지 않는다. 조회 캐시는 사용자·run별 격리와 짧은 TTL을 검토한다.
- 진행률 근거가 없으면 ‘분석 중’과 처리 범위를 표시한다. 임의 백분율·예상 종료시간을 만들지 않는다.
- 영상은 원본 기준 시각과 클립 내부 시각을 함께 연결한다. 만료된 Asset URL은 다시 발급받는다.
- 우선 기본 Streamlit 요소로 구성한다. FE는 Streamlit 서버에서 API로 파일을 전송하는 초안이며, 브라우저→S3 직접 업로드가 자동 지원된다고 가정하지 않는다.

## 반드시 구분할 화면 상태

queued/dispatching/running, 후보 먼저 도착한 enriching, 후보 없음, 미분류가 있는 partial, 분석 failed, VLM failed, RAG insufficient_evidence, 사람 unreviewed/판단 완료. 정확한 enum과 표시 조건은 공통 계약을 따른다.

‘사고 없음’ 대신 ‘분석된 범위에서 사고 의심 후보 없음’을 사용한다. 후보 점수와 검토자 판단을 같은 배지로 합치지 않는다. 초안이 바뀌면 이전 버전에 대한 검토임을 보여준다.

## 받을 것·넘길 것

- BE에서 API base URL, 계약 버전, 가상 응답, 오류·접속 방식, 영상 제한을 받는다.
- 모델 담당에게는 화면에서 필요한 원본 시각/클립 시작점/객체 좌표를 계약으로 요청한다.
- 산출물: 화면 구성, API client 연결, 상태별 표시, 사용자 흐름 확인 기록. 새로운 공통 필드는 계약에서 합의한다.

## 첫 작업과 완료 기준

첫 작업은 [가상 응답](../contracts/demo-analysis-cases-v0.2.json)으로 작업 목록·상세·검토 흐름을 설계하는 것이다. 실제 영상이 없는 예시에 빈 플레이어나 시연 표시를 사용하며 존재하지 않는 영상을 재생 가능하다고 만들지 않는다.

완료 확인: 새로고침·여러 클릭으로 새 작업이 늘지 않음, 새 세션에서 작업 조회 가능, 부분/실패 표시, API 오류 후 입력 유지, 검토 저장 후 재조회와 충돌 처리. 실제 서비스 API 연결 확인은 가상 화면 확인과 별도로 남긴다.
